# 后台主动消息与定时唤醒的生成生命周期

常驻服务的运行状态不能证明单条模型请求仍在接收内容。后台请求需要在整个生成、工具调用和
保存阶段拥有前台服务与 CPU 唤醒保护；错误状态的收尾只用于正确呈现结果，不能替代请求保护。

## 请求保护

- `ProactiveMessageTriggerService` 使用服务持有的监督作用域；销毁时取消其请求并释放锁。
- 在移交 IO 线程前获取每次任务独立的 partial WakeLock；正常结束及时释放，安全上限两小时。
  应用明确声明 `android.permission.WAKE_LOCK`，无需额外的运行时权限弹窗。
- 跟踪每个 Android `startId`；重复、被拒绝或提前结束的触发不能停止另一条仍在运行的任务。
  只有所有任务结束后才按最新 startId 结束服务。
- 后台生成成功取得会话所有权后，再在保存锁内读取当前会话。已取消的旧任务收尾不会被旧快照覆盖。
- Session 的任务替换与抢占使用同一同步锁；完成回调只允许清除自己的 Job，不清除后来替换它的任务。

## 进展、落盘与失败

- 每个原始模型片段均先合并，再合并保存完整快照；最多约每 500 毫秒落盘一次，降低长历史的
  Room/全文索引写入负担。正常结束或上游错误时先保存末尾快照；用户取消不延迟发送旧快照。
- 每个工具返回后立即记录已知结果。取消时尚未确认的结果标记为 `interrupted/unknown`，不自动重试。
- 每轮模型流有宽松边界：首次有效进展 15 分钟、后续无进展 10 分钟、单轮总计 30 分钟。
  空事件不延长有效进展期限；这些边界不包围工具执行，也不修改前台聊天和全局 HTTP 设置。
- 每轮模型输出执行转换器的结束钩子。请求成功、异常或取消时，只收尾本次拥有且仍存在的消息 ID，
  不重新插入用户删除的节点，不修改新请求；部分内容保留。仅全文为 `[PASS]` 才作为主动跳过删除。
- 思考中断会显示“思考已中断”；重新打开没有活跃任务的会话时修复旧的孤立思考记录。
  保活或网络异常会报告失败，不能用继续增长的计时假装请求仍在运行。
- 内容收尾与下一次主动消息调度分别有界，保存失败不会跳过调度；每日计划仍沿用提前重新设定下一次的机制。

## 验证与范围

虚拟时间测试覆盖流超时、心跳、取消、末尾快照、重复服务启动、旧 Job 完成回调及孤立状态恢复。
本次以第 17 版源码为基准保留界面与玻璃渲染，不携带第 18 版的边缘实验和截图测试依赖。

这些改动减少了可确认的后台请求中断路径，但不能保证系统强制停止、进程被杀或物理网络切换后
仍保留同一条 HTTP 流。需要在 P60 上锁屏、切后台并观察实际主动消息和定时唤醒；运行日志中的
startId、服务销毁和超时原因可用于区分后续问题。未实现断流后的自动模型/工具重放。

## 闹钟交接与执行结果

`last_triggered_at` 只证明计划被消费，不能证明模型请求或回复成功。闹钟接收器现在在同步
`onReceive` 内直接启动前台服务，不先交给 IO 协程读写计划。服务取得前台运行和 CPU 保护后，
才通过原有互斥与去重逻辑消费计划、读取最新备注和提示词并重排每日计划。

明确设置的定时唤醒最多等待现有会话任务及其收尾两分钟，再读取最新历史开始请求；普通随机
主动消息仍在繁忙时跳过。模型请求之前的上下文获取、输入转换与工具准备各有一分钟边界，
防止在流超时保护开始之前无期限等待。定时唤醒不再注入随机主动消息允许 `[PASS]` 的系统规则，
计划自身的唤醒提示词和用户的助手系统提示词仍正常使用。

每条计划增加兼容旧数据的可空 `execution`，绑定计划 ID 和该次 `scheduled_at`，记录最近阶段、
更新时间、对话 ID 和有界的通用说明。启动失败、会话忙、准备或模型失败、主动跳过、中断及
回复保存成功均分别记录；只有回复实际保存后才写 `completed`，不承诺通知已送达。重复投递、
旧轮次及迟到的阶段回调不能覆盖新执行或终态，也不会重新插入被取消的计划。`list_wakes`
与唤醒提示词页展示这些结果；旧数据只有触发时间时明确为无法确认，不补写虚假的成功状态。
没有新增人工创建、调时或取消入口，也没有自动重放可能已执行的模型或工具操作。

回复在本地保存后立即尝试提交通知，随后才等待可选的外置记忆同步；同步的慢请求或失败不会
阻塞这一通知尝试。通知与悬浮提醒分别处理失败，不影响已保存回复或后续记忆同步。同步返回的
`Result.failure` 会正确记入日志，而不被外层 `runCatching` 误认为成功。

执行说明记录通知尝试的秒级时间，并区分应用通知关闭、聊天通知类别关闭、权限检查失败、
通知接口异常及已提交系统。已提交系统仍不等于锁屏、横幅或声音实际展示；页面时间也精确到秒，
便于与进入 App 的时点对照。`COMPLETED` 始终只代表回复本地保存成功。

## 随机主动消息的冷启动与调度

后台入口和生成收尾必须等待 `Settings.init == false`，不能把 `Settings.dummy()` 中默认关闭的
主动消息当成用户真实设置。否则冷启动时可能直接跳过请求，甚至在收尾取消两路调度。
设置读取保留准备超时；读取失败不会按“用户已关闭”处理。

随机时间每轮只计算一次，AlarmManager、WorkManager 和设置页共用持久化的截止时间。
两路投递都携带该时间；服务在同一锁内确认它仍是当前已到期计划，预排下一轮后才开始生成。
重复投递、旧计划回调和过早投递不生成，也不推后当前计划。模型失败、会话繁忙或进程在生成中
终止不会依赖本轮请求的收尾才能续排；不自动重放可能已执行的模型或工具请求。

应用冷启动、更新、重启或重新获得精确闹钟权限时恢复已有截止时间，备用任务使用 `KEEP`，
不替换正在投递的工作；过期计划交给系统尽快投递一次，不按错过的周期连续补发。
修改间隔后会重排，缩短间隔可以实际提前；重新开启后的首次触发不受旧的最小间隔记录限制。
启停与调时间的系统副作用在设置保存完成后执行。用户发送消息导致的明确计时重置保持原行为。
固定时间的计划唤醒不会再重排随机主动消息的倒计时。

新增 JVM 回归覆盖占位设置后的延迟加载、真实关闭、加载取消与超时，以及共享截止时间、
冷启动与过期恢复、双源并发去重、缩短间隔、旧轮失效和极端间隔边界。
测试不能替代 P60 的实际投递验证；随机触发后模型仍可按现有规则返回 `[PASS]`，
已开启开关或到达计划时间不保证每一轮都产生可见消息。第 17 版聊天气泡和滚动实现保持原样。

## 每轮结果与接收对话

请求日志中的 HTTP 200 只表示已收到成功状态的响应头，其耗时也不包含后续整轮流式生成。
当前日志不保存成功流式请求的回复正文；不能据此确认模型已输出、已保存聊天或通知已展示。

「设置 → 主动消息 → 最近执行」展示最近五条记录，持久化上限八条。每条记录包含计划时间、
执行时间、最近更新时间、阶段或结果，以及可打开对应聊天的入口。准备、请求、接收内容、
工具执行、模型跳过、会话忙、语音来电、失败、中断和回复已保存分别显示；仅在本地保存调用
成功后记为回复已保存，通知结果单独显示。HTTP 200 不会直接把执行标为完成。
记录不保存模型正文、提示词、请求头或密钥，日志失败也不阻止原有模型流程。

每次执行有独立 ID，迟到阶段不能覆盖终态或恢复已清除的记录；工具执行后的下一轮请求仍可
正常记录。进程冷启动时，前次未记录终态的执行标为中断并明确无法确认结果，不自动重放请求。
此版本安装之前的成功流式请求没有回复结果可供补查，不推测为跳过或成功。

后台回复按接收助手下实际最近更新的对话选择目标。通用会话列表的置顶顺序不参与选择，避免
较旧的置顶聊天优先于刚聊过的对话。获取最近聊天上下文也使用同一接收助手和选择方式，
不受当前界面切到其他助手的影响。这修复了确定存在的误投路径，但不证明每次缺少可见消息
都由置顶会话导致；需结合执行结果和对应聊天核对。
