# 后台主动消息与定时唤醒的生成生命周期

常驻服务的运行状态不能证明单条模型请求仍在接收内容。后台请求需要在整个生成、工具调用和
保存阶段拥有前台服务与 CPU 唤醒保护；错误状态的收尾只用于正确呈现结果，不能替代请求保护。

## 请求保护

- `ProactiveMessageTriggerService` 使用服务持有的监督作用域；销毁时取消其请求并释放锁。
- 在移交 IO 线程前获取每次任务独立的 partial WakeLock；正常结束及时释放，安全上限两小时。
  应用明确声明 `android.permission.WAKE_LOCK`，无需额外的运行时权限弹窗。
- 跟踪每个 Android `startId`；重复、被拒绝或提前结束的触发不能停止另一条仍在运行的任务。
  只有所有任务结束后才按最新 startId 结束服务。
- 后台生成成功取得会话所有权后，再在保存锁内读取当前会话。已取消的旧任务收尾不会被旧快照覆盖。
- Session 的任务替换与抢占使用同一同步锁；完成回调只允许清除自己的 Job，不清除后来替换它的任务。

## 进展、落盘与失败

- 每个原始模型片段均先合并，再合并保存完整快照；最多约每 500 毫秒落盘一次，降低长历史的
  Room/全文索引写入负担。正常结束或上游错误时先保存末尾快照；用户取消不延迟发送旧快照。
- 每个工具返回后立即记录已知结果。取消时尚未确认的结果标记为 `interrupted/unknown`，不自动重试。
- 每轮模型流有宽松边界：首次有效进展 15 分钟、后续无进展 10 分钟、单轮总计 30 分钟。
  空事件不延长有效进展期限；这些边界不包围工具执行，也不修改前台聊天和全局 HTTP 设置。
- 每轮模型输出执行转换器的结束钩子。请求成功、异常或取消时，只收尾本次拥有且仍存在的消息 ID，
  不重新插入用户删除的节点，不修改新请求；部分内容保留。仅显式 `[PASS]` 才作为主动跳过删除。
- 思考中断会显示“思考已中断”；重新打开没有活跃任务的会话时修复旧的孤立思考记录。
  保活或网络异常会报告失败，不能用继续增长的计时假装请求仍在运行。
- 内容收尾与下一次主动消息调度分别有界，保存失败不会跳过调度；每日计划仍沿用提前重新设定下一次的机制。

## 验证与范围

虚拟时间测试覆盖流超时、心跳、取消、末尾快照、重复服务启动、旧 Job 完成回调及孤立状态恢复。
本次以第 17 版源码为基准保留界面与玻璃渲染，不携带第 18 版的边缘实验和截图测试依赖。

这些改动减少了可确认的后台请求中断路径，但不能保证系统强制停止、进程被杀或物理网络切换后
仍保留同一条 HTTP 流。需要在 P60 上锁屏、切后台并观察实际主动消息和定时唤醒；运行日志中的
startId、服务销毁和超时原因可用于区分后续问题。未实现断流后的自动模型/工具重放。
