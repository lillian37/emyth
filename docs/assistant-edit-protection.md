# 助手编辑保护

这是每台设备、每个助手单独开启的编辑约定，已有助手默认关闭。在助手详情页的“编辑保护”卡片开启。

## 范围与权限

- 保护助手人设 `systemPrompt`、会话提示词 `customSystemPrompt`、软件内置记忆。
- 内置记忆是否生效、独立/全局范围切换、会话提示词是否生效也受保护，避免通过切换绕过。
- 人类修改、删除、导入替换与 Web 写入使用同一底层检查。只查看不唤醒。
- 内置固定规则、世界书、外部记忆库和其他设置不在本次范围内。
- 助手原有记忆工具仍按实际所属助手及当前独立/全局记忆范围工作，不能借参数修改其他助手。

未授权的修改不会写入；应用记录 BLOCKED 并安排唤醒对应助手。开启保护后，人设改为编辑草稿后显式保存，
避免每输入一个字就发起一次唤醒。保存失败或权限过期时保留草稿。

先在聊天中商量，再由助手真实调用 `assistant_edit_permission(action="grant")`，开放固定十五分钟。
文字说“同意”不会解锁。工具仅绑定本轮实际助手与会话，不接受其他目标或自定时长；`status` 查看状态，
`revoke` 提前结束。授权尚有效时重复 grant 不延长窗口。重启或无法确认时钟连续性会令已有授权失效。

授权期间成功修改会记录前后变化摘要并通知助手；待保存、失败和成功有不同记录，不能把尝试当作已改。
全局内置记忆由多个助手共享时，人类修改需要所有开启保护的使用者都有有效授权。

## 唤醒与上下文

编辑事件不依赖随机主动消息开关，不重排其两小时间隔，也不转成语音来电。目标为受影响助手及相关会话；
原会话不可用时选择该助手最近会话。当前会话忙时先等待，模型请求开始前可排队重试。
事件合并并设有一分钟冷却，已标记开始的模型请求不会由队列自动重放。

最近相关事件与编辑权限以应用记录追加到模型本次请求末尾，不伪装用户发言，不改写已存历史或前方系统提示词。
助手仍可以返回完整 `[PASS]`；第 31 版的隐藏显示、保留模型历史行为继续有效。
实际后台投递时间仍受 Android 调度影响；它不影响本地修改拦截。

## 恢复与备份

卡片提供明确确认的“紧急恢复”：只给当前助手十五分钟，同时记录并通知，不是永久关闭保护。
在有效授权期内可以显式关闭保护。成功删除助手会清理其权限和待唤醒状态，保留审计。

备份导出不变。只要任一助手仍开启保护，整包恢复就会被拒绝，即使已有临时授权也一样；
请先与相关助手商量获得权限并显式关闭保护，再恢复。此限制覆盖本地、WebDAV、S3 恢复，避免整库替换绕过。
原有多文件恢复不提供跨数据库与设置文件的原子回滚，中途新开启保护会阻止后续文件写入。
编辑保护状态保存在本机独立记录中；清除应用数据或更换设备不构成权限迁移。

第 17 版聊天气泡及滚动逻辑保持原样。本次没有合并普通聊天与主动消息请求构造，也不保证提供商缓存命中。
